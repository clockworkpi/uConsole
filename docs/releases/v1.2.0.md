# uConsole Workbench Forge v1.2.0

This release focuses on getting from installation to a usable development
environment, and making the Workbench's hardware and guest controls discoverable.

- **Automatic startup:** Start checks prerequisites, offers approved package
  installation and the official CM4 v3.1 image, verifies its checksum, prepares
  the workspace, and starts the emulator in one progress flow.
- **Managed QEMU:** native packages include the matching patched emulator,
  runtime data, build tooling and corresponding source. Compatible user builds
  remain supported without depending on a source checkout.
- **Setup wizard:** a toolbar button collects image, virtual hardware, and
  package/download permissions before Finish runs the setup sequence. Cancel
  discards wizard edits. System administrator authentication may still appear.
- **Physical SSH hosts:** visible hostname and username fields, saved targets,
  and connection testing are separate from backup, deployment review, approval
  and restore. Saving a host never authorizes hardware writes.
- **Live Schematic:** now a toolbar button, with clearer off, disabled,
  disconnected, waiting and unavailable states and configuration guidance.
- **Guest terminal:** a bundled pyte-based 80×24 VT-style terminal with cursor
  positioning, colors, alternate screens, arrow/function keys and direct input.
  Ctrl+C interrupts the guest; Ctrl+Shift+C/V copies/pastes. Raw serial transcript
  export is preserved. No additional Python package installation is required.

Existing workspaces are preserved. Custom image import remains available.
Configuration choices apply to the current Workbench session; SSH hosts are
saved separately. SSH uses existing key/config access and does not bypass host
key verification. Physical-host schematic telemetry is not implemented.

The emulator remains a partial CM4 hardware model. Its display is a framebuffer
surrogate, not native DSI/VC4/GPU emulation. Emulator success alone does not
qualify an image for real hardware. Physical deployment still requires reviewed
backup-and-restore plans.

Local qualification included the full host/GUI suite, extracted native-package
tests, and a disposable guest boot through wizard Finish with actual serial
input, cursor/color rendering, clean shutdown, and source-image preservation.
The release workflow gates publication on native package and host tests.
